## Recreate and verify the Python environment

From a writable extracted release root containing `work/` and `outputs/`, with this folder at `work/repro_v3_environment/`:

```text
conda env create -f work/repro_v3_environment/environment.yml
conda activate ischemia-lr-repro
python work/repro_v3_environment/verify_environment.py --release-root .
python work/repro_validate.py --require-complete
python work/repro_run_cached_pipeline.py --execute --include-completed-optional --require-complete
```

The conda create command is supplied for execution by a reader and remains untested here. For a Python 3.12.14 venv, create a fresh environment, install `requirements-python.lock.txt` with that environment's `python -m pip install -r ...`, and run the same verification. Do not copy the original environment's `.pth` paths or machine-local artifact dependency into the new environment. The guarded cached pipeline reproduces saved aggregates and networks; it does not fit the cell-level models. The complete 12-stage cached reconstruction and 2,749-check validation were previously tested both in the original and relocated release directories using the frozen original interpreter.

## Restore R separately

Install R 4.6.1 for the target platform, then explicitly invoke:

```text
Rscript --vanilla work/repro_v3_environment/restore_r_environment.R work/repro_v3_environment
```

This opt-in script installs pinned renv 1.2.4 in `renv_bootstrap/` and restores the full lock into `r-library/`. It verifies all installed DESCRIPTION versions afterwards. **The full restore command has not been executed here.** Source compilation may require the appropriate toolchain/system libraries. The Windows R installer URL and checksum remain in `work/repro_decontx/installers/r_runtime_manifest.json`; R is separate from the Python conda environment. To execute an upstream R analysis using this restored library, pass the new library path explicitly to the existing R entry point. The recorded DecontX fits used the fixed original broad cell labels, seed 20260911 and convergence threshold 0.001, with the original 500 iterations and a separately retained 2,000-iteration numerical extension selected only by the recorded convergence rule.

## Two LIANA code paths, with different scopes

| Code path | What was actually executed | Reproduction entry point |
| --- | --- | --- |
| LIANA 1.10.0 native pipeline | Complete per-library inference on the original full cell-type background, including native scores and consensus, in the archived raw/corrected/third-cohort runs | Original raw source `work/revision_liana.py`; full-network/raw diagnostic execution snapshot `work/repro_liana_rank_diagnostic_raw_run.py`; corrected-source handling in the current diagnostic script |
| Fixed upstream commit `d4211373692e7b9c10210488ccb1efe06452b097` | Only four aggregation functions extracted from that commit and replayed on the unchanged 22 raw full-network score tables, restoring score dtype to float32 | `work/repro_upstream_correction_audit.py`, called by the guarded cached pipeline's `upstream` stage |

The fixed commit is the [official merged PR #261](https://github.com/scverse/liana/pull/261). Its aggregation source is archived from `src/liana/_core/_pipe_utils/_aggregate.py`; the original installed 1.10.0 source used `liana/method/_pipe_utils/_aggregate.py`. The archived hashes and AST comparison bind the tested implementation. The isolated replay agreed exactly with the unique-column diagnostic across all 22 networks, with maximum absolute difference zero. The logging stub is intentionally separate from the four unchanged aggregation function bodies.

The commit also changes defaults and other pipeline code. **A complete new-version LIANA cell-level pipeline was not run.** Thus the study compares native inference with a controlled aggregation correction; it is not a benchmark of two fully rerun software releases. Installing a newer package and letting new defaults propagate would answer a different question.

For a bounded replay in a writable release copy:

```text
python work/repro_run_cached_pipeline.py --stages raw_rank_summary upstream --execute --require-complete
```

This command summarizes the archived native target scores and replays the fixed aggregation. It does not install another LIANA package or open raw cell matrices. To reproduce original full cell-level inference from its upstream matrix/QC caches, the archived native execution is:

```text
python work/repro_liana_rank_diagnostic_raw_run.py --count-source raw --configs primary reference_singlet
```

The latter is a large upstream operation, requires the separately obtained input data/cache and uses existing completed outputs if present; it is not run by the cached entry point. The frozen snapshot is retained for raw provenance and should not be used as the current corrected-source convergence resolver.

## GitHub / Zenodo file placement

`release_file_sizes.tsv` inventories all ZIP members without extracting them; `release_files_over_100MB.tsv` explicitly distinguishes decimal 100 MB from GitHub's 100 MiB threshold.

- `code_results.zip`: 541,711,621 bytes (516.62 MiB). No individual member exceeds 100 MiB. This ZIP belongs in release assets or Zenodo, not a regular Git commit.
- `corrected_matrices.zip`: 2,421,437,340 bytes (2,309.26 MiB), exceeding 2 GiB. Twelve contained NPZ matrices exceed 100 MiB; the largest is approximately 334.15 MiB.
- Keep source code, locks, small metadata and documents in the GitHub repository. Store the intact matrix ZIP on Zenodo, or create separate cohort ZIP assets below 2 GiB for GitHub while preserving new per-asset checksums and member manifests. No split or publication was performed here.

GitHub [blocks regular Git files larger than 100 MiB](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github), and its [release documentation](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases) specifies a limit below 2 GiB per release asset. These distinct limits should not be conflated. Exclude `renv_tooling`, bootstrap/test libraries, R/Python runtimes and local cached-run backups from the repository; include the lock files, source metadata and audits.
